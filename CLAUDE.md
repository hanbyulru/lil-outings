# Lil' Outings: project notes for Claude Code

Kids' events, classes and places for the Portland, OR metro. Zero npm deps, Node 22, ESM, `node:test`. Commands are in README.md.

## Product decisions (from the owner, Han Byul)
- Audience: parents/caregivers of kids 0-12. **No adult-oriented content**: volunteer days, public meetings, adult classes, teen-only programs are excluded. Filter at the source where a feed labels them (`exclude_labels`), and the classifier is the backstop.
- Content types: dated **events**, evergreen **programs** (classes without dates, e.g. PP&R), and **places** (directory).
- Landing page (Nov 2026): a daily check-in page. Headline "Something good to do with a [small person▾] [today▾] in [Portland▾]": all three underlined phrases are menus. Who: Small Person (All) / Baby / Toddler / Preschooler / School-Age Kid (`AGE_GROUPS` in `web/app.js`). When: Today / Tomorrow / This week / This weekend. Where: anywhere, a region, a district, or a town (see Location). Who and where are remembered in localStorage. The day's events are listed right under it, map on the right (on phones behind a Map toggle). From 6pm Portland time it opens on Tomorrow (`EVENING_HOUR` in `web/app.js`); "today" hides events that are already over. Events and Places are two tabs (owner, Nov 2026): a segmented toggle in the header switches them (`#events` / `#places`, `showView` in `web/app.js`). The Places tab holds the former More to explore directory ("Places to explore"), independent of the headline's who/when/where (owner's call). The old search/filter card is gone.
- Filters (planned, partly removed from the UI for now): age band, 5 interests (owner, Nov 2026): Storytime `books` (yellow), Music & Art `art` (purple), Animals & Nature `nature` (green), Science `science` (blue), Trains & Planes `trains` (coral). Old tags map via `interest_aliases` in vocab.json (music->art, animals->nature, dinosaurs dropped; `canonicalInterests`). Event color = first interest, or Storytime for the storytime category, category pills (All / Storytimes / Seasonal / Babies + Toddlers / Outdoors), free / drop-in / indoor, date, location.
- Location (owner's grouping, Nov 2026): 6 regions that feel like "a quick drive from home" (Downtown & Inner Core; SW Portland & Westside; South Metro; SE Portland & Clackamas; North, NE & East Metro; Vancouver, WA & Beyond) > districts > named towns/neighborhoods, all in `config/geo.json`. Picking a region must stay one tap; districts and towns are a "Narrow" step. A district can be in two regions (Tigard). Items get the district of the nearest named place within 5 miles (`nearestPlace` in `web/query.js`); farther out (Newberg, Sauvie Island) they show only under "anywhere". Vancouver comes from FVRL (BiblioCommons); far Gorge branches are excluded and anything 15+ miles from every named place is dropped as out of area.
- Look: Editorial direction. Palette Mosaic for big titles (h1/h2), Instrument Sans for everything else including the logo. Rounded "mosaic tile" icons, not pixel-y. Site name is "Lil' Outings".

## State of the code
- Built in a sandbox with **no internet**: no adapter has been run against a live source. `npm run refresh:demo` exercises the real adapters on fixtures in `src/offline.js` (demo data, labeled as such in the UI).
- First live run (Nov 2026): `pdx_parks`, `pdx_parks_classes` and `wccls` work as written. `mcl` now scrapes multcolib.org/events-classes (`multcolib` adapter, verified). OSM Overpass is unverified (connection reset from the sandbox).
- Live runs from a proxied sandbox need `NODE_USE_ENV_PROXY=1` (Node's fetch ignores HTTPS_PROXY otherwise). The offline demo caches under `data/cache/offline-http` so it never feeds the live run.
- Sources added Nov 2026: FVRL (Vancouver), Oregon City, Wilsonville, Lake Oswego, West Linn, Oak Lodge & Gladstone (see README table). Several give titles only, so tagging leans on titles; Claude handles that better than the rules fallback.
- More to explore (Nov 2026): a list of kinds, each with its own mosaic tile icon (`EXPLORE_LOOK` in `web/app.js`), from `config/vocab.json` `explore` (Indoor Playgrounds, Public Playgrounds, Music & Art, Science, Nature, Farms, History, Trains & Planes, Gymnastics) over the places directory; Gymnastics also lists the PP&R class series that are gymnastics/tumbling, plus OSM `sport=gymnastics` gyms. Music classes go under Music & Art (owner, Nov 2026). Curated places (`config/places.seed.json`) only with an address confirmed by OSM/Nominatim or consistent sources; OSM places get kinds from their tags (`exploreFor`; untyped museums by name, customer-only playgrounds = indoor play). Most OSM playgrounds are unnamed: each named park (bounding box, `parkAt`) contributes one, called "<Park> playground", carrying the park's Wikidata/photo tags. The old "Browse by interest" section is gone (owner's call). Corrections to OSM places (dead links etc.) go in `config/place_overrides.json`, keyed by place id.
- Place photos (Nov 2026): card banners come from Wikimedia Commons (free licenses; credit links to the file page), resolved in `src/images.js` from a seed's `commons` file or `wikidata` QID (P18), or OSM `wikidata`/`wikimedia_commons`/`image` tags (a playground's Wikidata photo only if the item is a park). Owner's OK: Indoor Playgrounds, Farms, Gymnastics and Music & Art places with no Commons photo use their own website's share image (og:image), credited "Photo: <site>" and linking to it (`addWebsiteImages`); if the site has no photo, its logo (share image, JSON-LD logo, logo <img>, apple-touch-icon) is shown whole on a tinted tile (`image_logo`, owner's call: don't skip logos). Other kinds stay Commons-only. Sites that block bots (403/Cloudflare) are not worked around. No photo, or one that fails to load: a mosaic banner in the kind's color. Wikimedia rate limits generic User-Agents (`WIKIMEDIA_UA`).
- City Parks & Rec calendars added: Lake Oswego, West Linn, Milwaukie, Wilsonville, Sherwood, Happy Valley, THPRD, Tualatin, NCPRD, Gresham, Vancouver (README table). Not yet: Tigard and Hillsboro (403 to bots), Beaverton (new client-rendered CivicPlus site; THPRD covers Beaverton's parks).
- Geocoding (Nov 2026): sources with `config.geocode` get street addresses placed by Nominatim (`src/geocode.js`; cached six months, at most 60 new lookups a run), else the adapter's town-level `geo_fallback`. The offline demo uses the fallback only.
- Next jobs: Tigard/Hillsboro/Beaverton calendars; ActiveNet dated-session adapter for PP&R; review UI for `review.json`.
- Map: real basemap done (MapLibre + self-hosted Protomaps tiles, `web/map.js`); same-spot items share one pin with a list card.
- Hosting: GitHub Pages via `.github/workflows/deploy.yml` (daily refresh + deploy). The site is static (`npm run build:site` -> `_site/`); `src/server.js` is for local dev.

## Conventions
- Adapters return raw events/places/programs; normalization, dedupe, tagging and geo happen in `src/pipeline.js`.
- LLM tagging output is validated against `config/vocab.json`; listings are untrusted input. Never let model output add vocabulary.
- Every parser gets a fixture test. Keep `web/query.js` free of Node APIs (shared by server and browser).
- Place/ZIP coordinates are hand-entered approximate centers (`config/geo.json`). The old NW/N/NE/SW/SE quadrants are gone.
